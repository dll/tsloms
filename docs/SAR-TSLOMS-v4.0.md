## 三、数据链路贯通审核（本审计核心）

对新增管理模块逐链路核验「数据从哪来、到哪去、是否闭环一致」：

### 3.1 库存链路：采购 → 入库 → 领料 → 出库

```
供应商(suppliers) ──► 采购单(purchase_orders+items, PO单号)
                          │
                          ▼ ReceivePurchase（事务）
                          ├─ 更新已入库数 received_qty
                          ├─ 增物料库存 materials.stock
                          └─ 写入库流水 material_stocks type=in (ref=purchase)
                          │
工单(work_orders) ──► 领料出库 POST /inv/stocks/use（事务）
                          ├─ 校验工单+物料+库存充足
                          ├─ 扣减库存 materials.stock
                          ├─ 写出库流水 type=use (ref=repair, 关联工单/设备)
                          └─ 自动生成 repair_expenses type=material（金额=数量×单价）
```
**结论：✅ 贯通一致。** 出入库数量与库存增减由单事务同步保证；领料成本自动归集到对应工单/设备。

### 3.2 费用链路：工单 → 费用 → 成本统计

```
工单领料(use) ──► repair_expenses(type=material, 自动)  ┐
人工登记 ──► repair_expenses(type=labor/traffic/other)   ├─► ExpenseStats 分类型汇总
                                                         └─► 设备维修成本 TOP10
```
**结论：✅ 贯通一致。** 领料自动生成的耗材费用 + 人工登记费用统一进入费用统计；设备成本按 device_hw_id 聚合。

### 3.3 工单/设备关联完整性

- 领料时**必须**关联有效工单（工单不存在拒绝，`code=-1`）。
- 费用关联工单时**校验工单存在**并自动带出设备ID（本审计修复）。
- 出库流水绑定 `work_order_id` + `ref_id`（=工单ID）+ `ref_type=repair`，回查完整。

### 3.4 事务一致性

| 操作 | 涉及写入 | 事务 |
|------|----------|------|
| 采购入库 | items.received_qty + materials.stock + material_stocks | ✅ 单事务 |
| 工单领料 | materials.stock + material_stocks + repair_expenses | ✅ 单事务 |
| 库存调整 | materials.stock + material_stocks | ✅ 单事务 |

**结论：** 所有涉及库存/费用/流水的复合写操作均在**单个数据库事务**内完成，任一失败整体回滚，杜绝状态分裂。

### 3.5 报表一致性

库存统计（物料数/低库存/流水笔数/总金额）、费用统计（分类型/TOP设备）、仪表盘概览均由同一底层表聚合，口径一致。

## 四、本审计发现并已修复的问题

### 修复1（🔴 高，数据链路断点）——工单领料不自动归集成本

- **问题**：`POST /inv/stocks/use` 原只扣库存+写 `type=use` 流水，**不生成 `RepairExpense`（耗材费用）**。费用模块虽有 `material` 类型，但领料成本无法自动进入工单/设备维修成本统计，需手工再录，易漏记、成本与流水对不上。
- **修复**：`UseMaterialStock` 改为在同一事务内：扣库存 → 写 `type=use` 流水 → **自动创建 `RepairExpense`（type=material，金额=数量×单价，关联工单+设备，confirmed=false）**。领料成本自动归集，费用统计口径完整。（commit `4efa96a`）
- **验证**：`TestWorkOrderMaterialUse` 扩展断言自动费用单号/设备/金额；全量测试绿；生产 E2E 复测见 §六。

### 修复2（🟡 中，健壮性）——费用关联工单未校验存在

- **问题**：`SaveRepairExpense` 关联工单时 `First(&wo)` 失败被静默忽略，无效工单ID仍能记费用。
- **修复**：改为关联工单时**必须校验存在**，不存在直接 `code=-1`「关联工单不存在」；校验通过自动带出设备。（commit `4efa96a`）

### 修复3（🟢 已在往版本处理）——前端部署目标路径

- 前端正确部署至 `/opt/tsloms/packages/admin/dist`（nginx alias 指向），避免旧 bundle 被长期误服务。本审计复核确认线上服务为最新 bundle。
