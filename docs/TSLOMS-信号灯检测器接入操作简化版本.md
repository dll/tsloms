# TSLOMS 信号灯检测器接入操作（简化版）

> 适用对象：系统管理员、信号灯运维人员、检测器厂商实施人员
> 生产入口：`http://129.211.223.113:8092/tsloms/admin/`
> 目标：在系统页面生成 MQTT 凭据，配置检测器并完成“接入—设备—故障—工单”验证。

## 一、登录系统

1. 浏览器打开生产入口。
2. 输入管理员分配的系统账号、密码和页面验证码。
3. 登录成功后进入仪表盘。

> 系统登录密码、MQTT 密码不得写入文档、工单或群聊。

## 二、确认 MQTT 服务状态

1. 打开左侧菜单「检测器接入」。
2. 进入「真实硬件接入」。
3. 确认「当前连接」为「已连接」。
4. 核对订阅 Topic：`trafficLight/{网络号}/{站点号}/{硬件ID}/U`。

「已连接」表示 TSLOMS 后端已经连接 EMQX Broker；检测器仍需使用有效的专用账号接入。

## 三、在页面生成检测器 MQTT 账号

1. 由系统管理员进入「检测器接入 → 真实硬件接入」。
2. 点击「生成检测器 MQTT 账号」。
3. 系统通过 EMQX `built_in_database` 创建随机账号和密码。
4. 页面显示 Broker、用户名和密码后，立即复制并通过受控渠道交付检测器配置人员。

安全规则：

- 账号与服务端 MQTT 账号分离，便于审计和吊销；
- 密码只在创建成功的当前页面显示一次；
- 密码不写入 TSLOMS 数据库、服务日志或 Git 仓库；
- 刷新或离开页面后不能再次查看原密码，遗失时应重新创建账号；
- 检测器固件的用户名、密码通常最长 8 位，以厂商协议和实际固件为准。

如果点击生成失败，请由平台管理员检查后端是否已配置 EMQX 管理 API。普通用户不需要登录服务器操作。

## 四、确定检测器硬件 ID

平台支持以下格式：

| 场景 | 格式 | 示例 |
|---|---|---|
| 平台设备台账 | `LA` + IEM 编号后 8 位 | `LA82533848` |
| MQTT Topic / 二进制协议 | 后 8 位对应的 32 位值 | `82533848` / `0x82533848` |
| 历史设备兼容 | 1～8 位十六进制 ID | `1114006C` |

推荐先在「设备管理」预登记 `LA82533848`。设备实际以协议值 `82533848` 上报后，平台会匹配同一台设备并转为「已接入」，不会生成重复台账。

## 五、配置检测器

使用厂商工具 `trafficLightConf` 配置检测器：

| 参数 | 填写值 |
|---|---|
| `mqttServerUserIp` | `129.211.223.113` |
| `mqttServerPort` | `1883` |
| `mqttUserName` | 第三节页面生成的检测器专用账号 |
| `mqttPassword` | 第三节页面生成的一次性显示密码 |
| `mqttTopicPrefix` | `trafficLight` |
| `networkCode` / `stationCode` | 默认 `0`，按现场规划调整 |

硬件 ID 使用协议后 8 位，例如平台台账为 `LA82533848`：

```bash
./trafficLightConf 82533848
```

检测器应连接：

```text
tcp://129.211.223.113:1883
```

并发布到：

```text
trafficLight/0/0/82533848/U
```

正常工作顺序：

1. 上电后发送 `POWER_ON`；
2. 按周期发送 `CHECKIN`；
3. 检测到异常时立即发送 `ALARM`；
4. 接收后台通过 `/D` Topic 返回的时间同步或其它应答。

## 六、验证接入闭环

### 6.1 检测器接入页

- MQTT 状态为「已连接」；
- 在线设备数或活跃检测器数增加；
- 订阅 Topic 与设备发布 Topic 一致。

### 6.2 设备管理页

- 能按 `LA82533848` 找到预登记设备；
- 接入状态由「未接入」变为「已接入」；
- 在线状态为「在线」；
- 首次接入时间和最后签到时间正确；
- 不存在另一条 `82533848` 重复设备。

### 6.3 故障与工单

检测器发送有效 `ALARM` 后：

- 「故障管理」出现与该设备关联的故障记录；
- 故障类型、等级与错误码一致；
- 严重且研判确认的故障自动生成维修工单；
- 维修完成后，故障和工单状态能够闭环。

## 七、常见问题

| 现象 | 处理方法 |
|---|---|
| 页面显示 MQTT 未连接 | 联系平台管理员检查 TSLOMS 后端与 EMQX，不要重复生成设备账号 |
| 生成 MQTT 账号失败 | 检查 EMQX 管理 API 配置与管理员权限 |
| 检测器提示认证失败 | 确认使用最新生成的用户名和密码，检查 8 位长度限制和大小写 |
| Broker 已连接但设备不在线 | 检查检测器网络、Topic、二进制帧校验和及签到周期 |
| 产生重复设备 | 平台台账使用 `LA+后8位`，协议与 Topic 使用相同的后 8 位 |
| 密码遗失 | 原密码不可恢复，应重新生成检测器账号并更新设备配置 |
| 报废设备仍上报 | 平台不会自动恢复报废设备；确认设备已断电或经管理员恢复台账 |

## 八、接入完成标准

- MQTT Broker：已连接；
- 检测器：认证成功并持续签到；
- 设备台账：同一硬件只有一条记录，接入时间正确；
- 故障管理：有效告警可识别、可追溯；
- 工单管理：严重故障可生成工单并完成维修闭环。

以上全部通过，才视为检测器正式接入完成。
