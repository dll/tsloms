# TSLOMS 腾讯云部署故障排查记录

- 文档版本：V1.0
- 更新日期：2026-08-14
- 状态：已修复（需在服务器应用配置并 reload）

## 一、故障现象

腾讯云部署后，前端页面访问/API 请求报 **"请求失败"**（控制台实际为 404 / 网络错误）。

## 二、根因

**前端与 Nginx 的路径前缀不一致**，导致请求命不中 Nginx 的 location，返回 404。

- 前端（`packages/admin`）已编译为带 `/tsloms` 前缀的版本：
  - `vite.config.js`: `base: '/tsloms/admin/'`
  - `src/utils/request.ts`: `baseURL: '/tsloms/api/v1'`
  - 产物 `dist/index.html` 引用 `/tsloms/admin/assets/...`
  - 401 跳转地址为 `/tsloms/admin/login`
- 但 Nginx `deploy/nginx/tsloms.conf` 只有 `/admin`、`/api`、`/health`、`/` 这些 location，
  **没有 `/tsloms` 前缀的 location**。

结果：
1. 打开 `/tsloms/admin/` → Nginx 无 `/tsloms` location → **404**，后台界面加载不出来；
2. API 请求 `/tsloms/api/v1/...` → Nginx 同样 **404** → 前端 axios 捕获后提示 **"请求失败" / "网络错误"**。

## 三、修复方案

已在仓库内更新 `deploy/nginx/tsloms.conf`，**定稿为纯 `/tsloms` 前缀方案**：

- `location /tsloms/admin` → 静态托管 dist（history 路由 try_files 回退 index.html）
- `location /tsloms/api/` → `proxy_pass http://127.0.0.1:8093/api/`（剥离 `/tsloms` 前缀后转发，后端只认识 `/api/v1`）
- `location /tsloms/health` → 健康检查
- `location = /` → 重定向到 `/tsloms/admin/`

**不再保留无前缀路由**。访问入口统一为带 `/tsloms` 前缀；网关（Caddy）需将 `/tsloms` 前缀**原样转发**（不剥离）到本机 8092。

前端 `packages/admin` 已一致：`vite base='/tsloms/admin/'`、`request baseURL='/tsloms/api/v1'`、401 跳转 `/tsloms/admin/login`。

## 四、服务器操作步骤

1. 拉取更新：
   ```bash
   cd /opt/tsloms && git pull origin main
   ```
2. 校验 Nginx 配置语法：
   ```bash
   nginx -t
   ```
3. 重新加载 Nginx：
   ```bash
   nginx -s reload   # 或 systemctl reload nginx
   ```
4. 确认后端服务在运行：
   ```bash
   systemctl status tsloms-server
   curl -s http://127.0.0.1:8093/api/v1/health
   ```
5. 验证访问（按部署网关的实际域名/路径）：
   - 直接访问：`http://<公网IP>:8092/tsloms/admin/`
   - 通过网关（Caddy 需保留前缀转发）：`https://<域名>/tsloms/admin/`

## 五、注意事项

- 网关（Caddy）必须将 `/tsloms` 前缀**原样保留**转发到本机 8092（`reverse_proxy` 时不要用 `handle_path`/`strip_prefix` 剥离）。若改用无前缀方案，需同时回退前端 `base`/`baseURL`，不可混用。
- 若线上后端未包含最近的响应体封装优化（`{code, msg, data}` 统一结构），请一并拉取最新 `server` 代码并重新编译：
  ```bash
  cd /opt/tsloms/packages/server && go build -o server cmd/server/main.go && systemctl restart tsloms-server
  ```
- 修改任何 Nginx location 前，务必先 `nginx -t` 再 reload。
