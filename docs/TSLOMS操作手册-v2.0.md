## 1. 系统简介

### 1.1 系统概述

TSLOMS（Traffic Signal Light Operation & Maintenance System，交通信号灯运维系统）是一套面向城市交通信号灯设备的 **AI 化在线运维管理平台**。系统通过 MQTT 协议实时接入信号灯检测器，在**后端全自动**完成设备数据汇聚、故障研判、工单闭环、成本归集，并以 AI 能力实现**主动巡检、流程辅助、自然语言交互、决策建议**，推动传统「人工运维」向「**无人值守、预判预修、自动闭环**」转型。

系统形态为 **Web 管理端（浏览器访问）+ 后端服务**，支持 Chrome / Edge 等主流浏览器，平板与手机浏览器可响应式使用（不提供独立移动端 APP / 小程序）。

### 1.2 价值主线

系统围绕运维全生命周期构建「**感知 → 研判 → 处置 → 闭环 → 预测 → 决策**」主线：

```
设备信号  ──MQTT──▶  感知采集 / 清洗降噪
                          │ AI 故障研判（分级定级 / 根因分析）
                          ▼
                    自动建单 / 工单流转 / SLA 督办
                          │ 领料出库 / 成本归集
                          ▼
                    运维闭环 / 报告沉淀
                          │ AI 预测 / 健康评估
                          ▼
                    决策建议中心 / 实时异常流（L6）
```

| 模块 | 功能说明 |

| 故障管理 | 故障自动/手动登记、四态生命周期、AI 处置建议 |

### 1.4 术语说明

| 术语 | 说明 |
|------|------|
| HW ID | 设备硬件唯一标识（uint32），MQTT 话题 `trafficLight/{hw_id}/...` |
| 故障四态 | occurred（发生）→ confirmed（已确认）→ dispatched（已派单）→ closed（已闭环） |
| 工单状态 | pending（待处理）→ processing（处理中）→ completed（已完成）/ closed（已闭环） |
| 领料 | 维修工单从物料库存中出库耗材，系统自动按 数量×单价 生成耗材费用 |
| SLA | 服务等级约定，工单超时自动升级提醒 |
| 运维健康评分 | L6 决策中心对全系统 0-100 的综合评分，含 6 项分维度 |
| 巡检 | 系统每日定时自动执行的运维日报生成 + 异常检测 + 站内通知推送 |

## 2. 突出特色

### 2.1 AI 融入运维全流程（不是独立工具）

TSLOMS 的 AI 不是"独立菜单"或"额外开关"，而是**深度嵌入每个关键操作节点**：

- **故障处理弹窗**内一键生成处置建议（摘要/优先级/预案/备件）；
- **工单完成弹窗**一键生成维修小结并自动填入表单；
- **新建工单/设备/采购**弹窗内 AI 校验、推荐、预填；
- **顶部 AI 助手**支持自然语言查询、报修、建单、知识库问答。

### 2.2 无人值守的 AI 主动服务

- 系统**每日定时**自动生成运维日报并做异常检测（超时工单 / 高风险设备 / 低库存缺货），推送到站内通知中心；
- 部署启动即触发一次巡检，第一时间产出日报与预警；
- 故障实时上报→AI 研判→自动建单，构成 **MQTT 传入即处置**的自动闭环。

### 2.3 L6 决策建议中心（自动闭环行动）

- 实时聚合设备/故障/工单/成本/库存，输出**运维健康综合评分（0-100）**与分维度评分、**可执行决策建议**；
- 备件采购类建议支持**一键采纳**：自动生成采购草稿单，人工确认后进入采购流程（半自动执行）。

### 2.4 六级 AI 化演进路线清晰

| 层级 | 能力 | 状态 |
|:---:|---|---|
| L1 | 基础 AI 功能（工作台/预测/诊断/额度） | ✅ |
| L2 | AI 原生增强（运维报告/专项分析/流程建议） | ✅ |
| L3 | AI 主动服务（定时巡检 + 异常预警 + 站内推送） | ✅ |
| L4 | 流程 AI 辅助（全操作表单嵌入 Copilot） | ✅ |
| L5 | 自然语言交互（顶部 AI 助手 / 报修建单 / 知识库 RAG） | ✅ |
| L6 | 自主决策（决策建议中心 / 实时异常流） | ✅ |

### 2.5 自动化业务闭环

- **故障生命周期**：设备上报 → 自动研判 → 确认 → 派单 → 处置 → 闭环，全程可追溯；
- **工单领料闭环**：领料出库在同一事务内扣库存 + 写流水 + **自动生成耗材费用**，无需手工录费；
- **采购闭环**：到货入库自动增加库存并生成入库流水；
- **费用归集**：手工 + 领料自动两类来源统一口径，成本统计支撑降本分析。

### 2.6 精细化 RBAC 权限体系

- 内置三角色（admin / operator / viewer）按 **28 个功能权限点**授予；
- 支持**自定义角色**、**用户级功能权限覆写**；
- 后端中间件按功能点强制校验，前端菜单/按钮联动隐藏，双重保障。

### 2.7 全链路数据可追溯

- 每台设备**全生命周期**（上线、故障、维修、领料、费用）可 AI 溯源；
- **操作日志**记录登录/设备/工单/费用/库存/采购等关键操作；
- **报文日志**记录 MQTT 收发，支撑故障排查与协议核对；
- **库存流水 / 升级记录 / AI 报告历史**完整留存。

### 2.8 高性能与健壮性（本次重构优化）

- 工单/故障**列表 N+1 查询消除**：批量预取，大数据量下响应更稳；
- **MQTT 热路径写节流**：去重窗口内无变化时减少无意义写入，`last_seen` 始终推进保持 30 分钟去重窗口锚点；
- **统一日志单例**（`LOG_LEVEL` 可配置）便于排障；
- 无 LLM 密钥时**规则引擎自动兜底**，AI 功能永不因外部依赖而不可用。

### 2.9 模块化 / 插件化（按甲方购买加载）

- 主菜单按**模块**划分：**核心基础模块恒启**（仪表盘/设备管理/路口管理/地图大屏/问题反馈/故障管理/工单管理/固件管理/系统日志/系统设置），**其它模块可选**（视频监控/物料库存/采购管理/维修费用/供应商/AI 分析等），默认不加载；
- 甲方购买的模块才加载，未购模块**菜单不显示、路由不可访问、后端接口 403**（双端拦截）；
- 已购可选模块经**环境变量 `ENABLED_MODULES`**（逗号分隔）配置启用；
- 核心模块即使未配置也始终可用，保证基础运维不中断。

## 3. 系统架构与组成

### 3.1 架构总览

```
浏览器 (Web 管理端)
   │  https://<域名>/tsloms/admin/
   ▼
Nginx (80/443 网关, 8092 内部)
   ├─ /tsloms/admin/  → 前端静态文件 (packages/admin/dist)
   ├─ /tsloms/api/    → 后端 API (反向代理到 127.0.0.1:8093/api/)
   ├─ /tsloms/media/  → 上传的媒体文件
   └─ /tsloms/health  → 健康检查
        ▼
后端服务 (Go, tsloms-server, 端口 8093)
   ├─ MySQL (tsloms 库)  ── 业务数据
   ├─ Redis (DB 1)       ── 缓存/会话辅助
   └─ MQTT Broker (1883) ── 信号灯检测器接入
        ▼
信号灯检测器设备 (MQTT 客户端, trafficLight/{hw_id}/...)
```

### 3.2 组件清单

| 组件 | 技术/版本 | 说明 |
|------|-----------|------|
| 前端 | Vue 3 + TypeScript + Element Plus + Vite + ECharts + Cesium | `packages/admin` |
| 后端 | Go（gin + gorm），纯静态编译（CGO_ENABLED=0） | `packages/server` |
| 数据库 | MySQL 8.x | 库名 `tsloms` |
| 缓存 | Redis 6.x+ | 使用 DB 1 |
| 消息 | MQTT Broker（EMQX / Mosquitto 等） | 端口 1883 |
| 反向代理 | Nginx | 对外 80/443，内部 8092 |
| 进程管理 | systemd（tsloms-server） | Linux 部署 |

### 3.3 主要端口

| 端口 | 用途 |
|------|------|
| 8092 | Nginx 内部服务端口（承载 admin + API 代理） |
| 8093 | 后端服务监听端口 |
| 3306 | MySQL |
| 6379 | Redis |
| 1883 | MQTT Broker |

## 4. 安装

### 4.1 前置环境要求

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| 操作系统 | Ubuntu 20.04/22.04 x64（或同类 Linux） | 生产建议 Linux |
| Go | 1.21+ | 仅构建后端需要 |
| Node.js | 18+ / npm | 仅构建前端需要 |
| MySQL | 8.x | 运行时必选 |
| Redis | 6.x+ | 运行时必选 |
| MQTT Broker | EMQX / Mosquitto | 运行时必选（对接设备） |
| Nginx | 1.18+ | 运行时可选（建议） |

> 生产环境运行仅需 MySQL / Redis / MQTT / Nginx + 编译好的二进制与前端产物；Go 与 Node 仅在**构建**时需要。

### 4.2 源码获取

```bash
git clone <仓库地址> tsloms
cd tsloms
```

项目根目录结构：

```
tsloms/
├── docs/                 # 需求/审核/协议文档
├── deploy/               # 部署配置（nginx/systemd/docker-compose/脚本）
├── packages/
│   ├── admin/            # 前端工程（Vue3）
│   └── server/           # 后端工程（Go）
└── AGENTS.md
```

### 4.3 后端依赖与构建

```bash
cd packages/server

# 设置 Go 模块代理（国内环境建议）
export GOPROXY=https://goproxy.cn,direct

# 下载依赖
go mod download

# 本地开发构建
go build -o server cmd/server/main.go

# 纯静态交叉编译（Linux 生产，CGO_ENABLED=0 避免 libc 依赖）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o server-linux cmd/server/main.go
```

### 4.4 前端依赖与构建

```bash
cd packages/admin

npm install          # 安装依赖
npx vue-tsc --noEmit # 类型检查（质量门）
npx eslint --fix    # Lint 修复（质量门）
npm run build       # 生产构建（产物在 dist/，base 为 /tsloms/admin/）
```

> 前端构建产物 `packages/admin/dist` 即 Nginx 静态目录内容。

### 4.5 数据库初始化

后端启动时自动完成建表与基础数据初始化（含默认管理员，仅当 `users` 表为空时创建）：

| 默认项 | 值 |
|--------|-----|
| 管理员用户名 | `admin` |
| 初始密码 | 由 `ADMIN_INIT_PASSWORD` 指定；为空则生成 16 位随机强密码并在首次启动日志打印一次 |

> 生产环境务必在首次登录后立即修改默认密码（系统强密码策略：≥10 位 + 字母 + 数字）。

## 5. 部署

### 5.1 部署目录约定

```
/opt/tsloms/
├── packages/
│   ├── server/
│   │   ├── server            # 后端二进制
│   │   └── uploads/media/    # 上传媒体（视频/图片）
│   └── admin/dist/           # 前端静态产物
├── nginx/tsloms.conf         # Nginx 站点配置
└── systemd/                  # systemd unit
```

### 5.2 systemd 服务配置

创建 `/etc/systemd/system/tsloms-server.service`（参考 `deploy/systemd/tsloms-server.service`）：

```ini
[Unit]
Description=TSLOMS Server
After=network.target mysql.service redis.service

[Service]
Type=simple
User=tsloms
Group=tsloms
WorkingDirectory=/opt/tsloms/packages/server
ExecStart=/opt/tsloms/packages/server/server
Restart=always
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/tsloms/packages/server

# 环境变量（按实际填写，敏感项建议从环境注入）
Environment=SERVER_PORT=8093
Environment=APP_ENV=production
Environment=DB_DRIVER=mysql
Environment=DB_HOST=localhost
Environment=DB_PORT=3306
Environment=DB_USER=tsloms
Environment=DB_PASSWORD=***
Environment=DB_NAME=tsloms
Environment=REDIS_ADDR=localhost:6379
Environment=REDIS_PASS=
Environment=REDIS_DB=1
Environment=JWT_SECRET=***
Environment=MQTT_BROKER=tcp://localhost:1883
Environment=MQTT_USERNAME=
Environment=MQTT_PASSWORD=
Environment=MQTT_TOPIC_PREFIX=trafficLight
Environment=LOG_LEVEL=info

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable tsloms-server
sudo systemctl start tsloms-server
```

### 5.3 Nginx 站点配置

参考 `deploy/nginx/tsloms.conf`。核心要点：

- 前端 `location /tsloms/admin` → `alias /opt/tsloms/packages/admin/dist`，history 路由回退 `index.html`；
- API `location /tsloms/api/` → `proxy_pass http://127.0.0.1:8093/api/`；
- 媒体 `location /tsloms/media/` → `alias .../uploads/media/`；
- 健康检查 `location /tsloms/health` → 后端 `health`；
- 路径统一带 `/tsloms` 前缀；网关（如 Caddy）应原样转发 `/tsloms`，不剥离前缀。

```bash
sudo cp deploy/nginx/tsloms.conf /etc/nginx/conf.d/tsloms.conf
sudo nginx -t && sudo systemctl reload nginx
```

### 5.4 部署验证（健康检查）

```bash
systemctl is-active tsloms-server                 # 期望: active
curl -s http://127.0.0.1:8093/api/v1/health       # 期望: 200/OK
curl -s http://<公网IP>:8092/tsloms/health        # 经 Nginx 探活
# 访问 http://<公网IP>:8092/tsloms/admin/         # 期望: 登录页正常
```

### 5.5 上线/升级部署（原子替换）

后端为**单二进制**，升级采用「备份 → 替换 → 重启 → 验证」原子流程：

```bash
cp /opt/tsloms/packages/server/server /opt/tsloms/packages/server/server.prev
scp -i ~/.ssh/wxx_deploy.pem server-linux root@<server>:/tmp/server.new
ssh -i ~/.ssh/wxx_deploy.pem root@<server> "
  install -m 0755 /tmp/server.new /opt/tsloms/packages/server/server &&
  systemctl restart tsloms-server &&
  sleep 3 &&
  systemctl is-active tsloms-server &&
  curl -sf http://127.0.0.1:8093/api/v1/health"
```

> 前端升级：将新 `dist` 内容替换到 `/opt/tsloms/packages/admin/dist` 即可（无需重启后端）。

### 5.6 常用运维命令

```bash
sudo systemctl status tsloms-server   # 查看状态
sudo systemctl restart tsloms-server  # 重启
sudo journalctl -u tsloms-server -f   # 实时日志
sudo systemctl reload nginx           # 重载 Nginx
```

## 6. 登录与界面

### 6.1 登录

1. 浏览器打开 `http://<服务器IP或域名>:8092/tsloms/admin/`；
2. 输入用户名与密码，点击「登录」；
3. 登录成功进入仪表盘首页。

## 8. AI 化运维

> 平台 AI 化按**六级演进路线**推进（详见 `docs/PRD-TSLOMS-v4.3.md`），当前 L1–L6 均已上线：
> L1 基础 AI → L2 AI 原生增强 → L3 AI 主动服务 → L4 流程 AI 辅助 → L5 自然语言交互 → L6 自主决策。

### 8.1 AI 工作台（L1/L2）

入口：**AI 分析 → AI 工作台**。

**① 库存健康分析**
- 点击「运行库存 AI 分析」：展示物料种类/总库存/总金额、低库存/缺货预警、滞销积压（近 90 天无领用）、近 6 月领用趋势，并由 AI 生成库存健康洞察与补货建议；无 LLM 时规则兜底。

**② 成本归因分析**
- 选统计周期（近 30/90/180 天），点击「运行成本 AI 分析」：展示成本结构（耗材/人工/交通/其它）、高成本设备、高成本故障类型，AI 生成成本归因与降本建议。

**③ 运维报告**
- 一键生成**运维日报**或**库存/成本/故障/工单/设备**模块报告；报告自动保存，可在「历史报告」查看/展开结构化数据。

### 8.2 AI 主动巡检与站内通知（L3）

- 系统**每日定时**自动生成**运维日报**（默认 08:00，可用 `PATROL_DAILY_HOUR`/`PATROL_DAILY_MIN` 调整），并做**异常检测**：超时工单、高风险设备、低库存/缺货；
- 检测结果以**站内通知**推送：顶部**铃铛**（红点=未读）→ 通知中心面板查看日报/预警、点击跳转对应模块、单条或全部已读；
- 服务启动时即执行一次巡检，便于部署后立即有日报与预警。

### 8.3 流程 AI 助手（L4，嵌入式）

AI 镶嵌在关键操作弹窗内，**一键生成、可填入、不强制**：

| 场景 | AI 能力 |
|---|---|
| 故障处理弹窗 | 生成处置建议（摘要/优先级 P0-P2/应对预案/建议备件），辅助确认/派单 |
| 工单完成弹窗 | 一键生成维修小结（根因/步骤）并填入「维修结果」 |
| 新建工单弹窗 | 建单建议（优先级/预领备件/步骤/推荐维修人），可预选维修人员 |
| 设备新建/编辑 | 依据已录字段给出填写/配置建议与校验提醒（hw_id 唯一性等） |
| 采购新建弹窗 | 采购明细合理性校验 + 供应商建议 |

> AI 建议均**嵌入式**：可一键填入，人工核对后保存；后端无 LLM 密钥时自动规则兜底。

### 8.4 AI 助手（自然语言交互，L5）

- 点顶部右侧「AI 助手」**魔法棒**图标打开对话面板；
- 用自然语言**查询 / 命令 / 咨询**：
  - **查询**：「最近7天哪些路口故障最多」「查询设备123456状态」「工单统计」「最近30天维修费用」；
  - **命令**（真实写入）：「报修：人民路与建设路交叉口红灯不亮」自动转结构化故障单、「给设备1建工单」命令式建单；
  - **咨询**：「怎么新建工单？」（知识库 RAG 直接回答）。
- 面板提供**快捷建议**，点击即发示例问题；AI 回答标注「来源」（LLM/规则）与命中工具类型。

> **命令类为写操作**，会真实创建故障单/工单并记录操作日志，操作前请确认输入正确。

### 8.5 AI 决策建议中心（L6）

- 进入 **AI 工作台 → 决策建议中心**，点「生成运维健康评分与决策建议」；
- 展示**运维健康综合评分（0-100）**及 6 项分维度（设备在线率/未解决故障/工单超时/工单闭环/运维成本/备件库存），并给**可执行决策建议**（人力排班、备件采购预测、成本优化、设备运维）；
- 对**备件采购**类建议点「**一键采纳**」，系统自动生成采购草稿单（半自动执行），在采购管理中查看/完善后下单；
- 也可在 **AI 助手**直接输入「运维健康评分」或「给出决策建议」快速查看。

### 8.6 AI 实时异常流（L6）

- 进入 **AI 工作台 → 实时异常流**，选时间窗（近 24 小时/近 3 天/近 7 天）查看时间倒序异常事件流，按严重程度（严重/重要/次要）分色；
- 异常来源四类：**设备报警报文/无效帧**、**活跃未解决故障**、**超时未闭环工单**（待处理超 24h、处理中超 48h）、**离线设备**；
- 顶部展示各类异常统计与 AI 结论摘要；无异常提示「系统运行平稳」；
- 也可在 **AI 助手**输入「最近有哪些异常/告警」快速查询；
- 说明：本页为请求时聚合的实时异常视图，配合 MQTT 传入即研判自动建单链路，构成 L6 实时异常检视闭环；需权限 `ai:ops`。

### 8.7 AI 兜底策略

全平台 AI 功能遵循**规则引擎兜底**：无 LLM 密钥 / 超额 / 调用失败时，自动降级为规则分析返回结构化要点（来源标记「规则分析」），功能始终可用，不影响运维操作进行。

## 9. 角色与权限（RBAC）

平台采用**可配置 RBAC 权限体系**：内置三种角色（按功能权限点授予），并可创建**自定义角色**、为单个用户**覆写功能权限**。后端中间件按功能点强制校验，前端菜单/按钮联动隐藏。

### 9.1 功能权限点（28 个，按模块）

设备、路口、故障、工单、媒体、固件、库存、供应商、采购、维修费用、用户、组织、角色、AI 共 14 模块，每模块含 create/update/delete/manage 等权限点（如 `device:create`、`fault:update`、`user:manage`、`role:manage`）。

### 9.2 内置三角色默认权限

| 权限 | admin | operator | viewer |
|------|:---:|:---:|:---:|
| 查看（设备/故障/工单/媒体/固件/物料/库存/采购/费用/日志/AI 预测） | ✅ | ✅ | ✅ |
| 设备/路口/故障/工单/媒体/固件/物料/库存/供应商/采购/费用等**业务写入** | ✅ | ✅ | ❌ |
| 业务数据删除（设备/物料/供应商/采购/费用/工单） | ✅ | ❌ | ❌ |
| 用户/组织/角色管理（`user:manage`/`dept:manage`/`role:manage`） | ✅ | ❌ | ❌ |
| AI 配置/用量（`ai:config`） | ✅ | ❌ | ❌ |
| AI 工作台与操作（`ai:ops`：库存/成本分析、日报、预测、流程建议、决策中心、异常流） | ✅ | ✅ | ❌ |

> **系统设置**入口对登录用户按角色显隐：拥有 `user:manage`/`dept:manage`/`role:manage` 任一才显示。

### 9.3 自定义角色与用户级覆写

- **角色管理**（系统设置 → 角色管理）：新增/编辑/删除自定义角色，按功能权限点勾选；内置角色不可改。
- **用户管理**（系统设置 → 用户管理）：指定角色，并可勾选**自定义功能权限**（不勾选则继承角色默认；勾选后可精细授权/拒绝）。

## 10. 角色操作流程

> 本章按三种内置角色给出端到端操作指引。实际权限以系统内配置为准（支持自定义角色与用户级覆写）。

### 10.1 管理员（admin）

**职责**：系统治理、全局配置、权限分配、高危操作与删除。

**① 上线初期配置（一次性）**
1. 登录 → 修改默认密码（系统设置 → 用户）；
2. 新建账号：运维人员（operator）、只读人员（viewer），并指定角色/自定义权限；
3. 录入组织（部门管理）、路口（路口管理）、设备（设备管理）；
4. 录入供应商、物料档案与期初库存；
5. 配置 AI（系统设置 → AI 配置：模型地址/密钥/额度；无密钥则规则兜底）；
6. 确认 MQTT 接入与设备在线。

**② 日常治理**
- 权限维护：新建/调整用户、角色、功能权限点覆写；
- 高危操作：删除业务数据（设备/物料/供应商/采购/费用/工单）；
- AI 额度管理：查看/调整/重置 AI 用量与每日限制；
- 通知处理：查看巡检日报/预警，指派处理。

**③ AI 决策使用**
- 进入 AI 工作台 → 决策建议中心，生成运维健康评分与决策建议；
- 对备件采购建议「一键采纳」，在采购管理中完善并下单。

**④ 审计与排障**
- 查看操作日志、报文日志；
- 阅读 AI 报告历史，跟踪运维质量。

---

### 10.2 运维人员（operator）

**职责**：业务执行——故障处置、工单闭环、采购入库、库存领料、AI 辅助使用。

**① 故障处置闭环**
1. 进入「故障管理」查看待处置故障（自动 + 手动）;
2. 点故障「处理」弹窗 → 点击「🤖 AI 助手 → 生成建议」，参考优先级/预案/备件；
3. 确认故障，派单生成工单，指派运维人员；
4. 处理完成后在工单中发起**闭环**。

**② 工单流转 + 领料**
1. 进入「工单管理」，处理指派给己的工单；
2. 处理中：从「物料库存」领用耗材出库（自动生成费用）；
3. 完成时：点击「🤖 AI 助手 → 生成建议 → 填入表单」，AI 生成维修小结填入「维修结果」，人工核对后保存，工单流转到 completed。

**③ 采购与入库**
- 采购管理 → 新建采购单（可用 AI 校验/供应商建议）→ 到货入库（自动加库存）。

**④ AI 辅助查询**
- 顶部 AI 助手用自然语言查询故障排行、设备状态、工单统计、费用归因；
- AI 工作台 → 库存/成本分析、运维报告；
- 查看通知中心日报与预警。

---

### 10.3 只读人员（viewer）

**职责**：查看与监督，无业务写入权限。

1. 查看仪表盘、设备/路口/地图、故障/工单状态、库存/采购/费用等；
2. 阅读 AI 预测、故障诊断、生命周期追溯；
3. 查看系统日志（只读）；
4. **不拥有** AI 工作台操作权限（`ai:ops`），不能生成报告/分析或使用写操作。

> viewer 账号仅用于监督/审计，不参与业务写入；如需参与运维执行，请为其分配 operator 角色或相应功能权限点。

## 11. 常见问题（FAQ）

### 11.1 登录相关

**Q1：登录后一直跳回登录页？**
- 原因：token 失效（默认 72h）或浏览器未启用 Cookie/本地存储。
- 处理：清除浏览器缓存重新登录；确认服务器与客户端时间偏差不大（超 5 分钟会致 JWT 失效）。

**Q2：忘记管理员密码？**
- 处理：由 DBA 在 `users` 表重置该用户密码（bcrypt 哈希），或保持一个可用 admin 账号；系统不提供找回功能，请务必记录。

**Q3：密码强度校验失败？**
- 系统要求 ≥10 位且同时包含字母与数字。

### 11.2 部署与连不通

**Q4：访问后台 404 或白屏？**
- 确认 Nginx `alias` 指向 `/opt/tsloms/packages/admin/dist`；`try_files` 回退 `index.html`；`nginx -t` + `reload nginx`。

**Q5：API 请求 404 / 502？**
- 确认后端启动（`systemctl is-active tsloms-server`）；Nginx `proxy_pass` 指向 `http://127.0.0.1:8093/api/`（剥离 `/tsloms` 前缀）；`curl` 探活。

**Q6：健康检查 `/tsloms/health` 失败？**
- 确认代理到 `http://127.0.0.1:8093/api/v1/health`；`journalctl -u tsloms-server -f` 查错。

**Q7：接口报跨域（CORS）？**
- 生产同域 Nginx 代理无跨域；前后端分离部署时需在 CORS 中间件配置正确的生产白名单域名。

### 11.3 数据库 / 数据

**Q8：后端启动失败报数据库连接错误？**
- 检查与 systemd 环境变量一致的 MySQL 账号/库名；`DB_HOST/DB_PORT` 可达；首次启动确保 `users` 表为空以触发默认 admin 初始化。

**Q9：领料后库存对不上？**
- 领料为单事务（扣库存+流水+费用），正常无差额；若异常先看「库存流水」「操作日志」，用「库存调整」修正，并核查是否并发扣减。

**Q10：工单领料没自动生成费用？**
- 确认后端为含自动费用修复的版本；领料成功后「维修费用」应有 `type=material` 记录；缺失则检查后端是否最新。

### 11.4 MQTT 与设备

**Q11：设备一直显示离线？**
- 确认设备连上 MQTT Broker（1883）；话题前缀 `trafficLight/{hw_id}/...` 匹配；查看报文日志；检查离线判定阈值。

**Q12：设备上报报文但未解析出故障？**
- 核对报文严格符合协议（token/ver/checksum/大端）；errCode 在已知 15 种故障含义内；查看报文日志与《设备协议确认清单》。

### 11.5 固件 OTA

**Q13：固件升级下发后设备无响应？**
- 确认设备端支持 `CMD_UPDATE_CONFIG`/`CMD_REBOOT`；此项依赖设备能力，硬件不支持则无法完成（已知硬件依赖）。

### 11.6 性能与容量

**Q14：地图大屏加载慢？**
- 首屏 Cesium 资源较大（已 manualChunks 分包）；建议 CDN/本地缓存；确认带宽。

**Q15：报文日志量大影响性能？**
- 报文日志建议异步化/分区归档（后续迭代）；当前可清理历史或调整保留策略。

### 11.7 AI 工作台 / 主动巡检 / 决策中心

**Q16：AI 分析/报告没生成洞察？**
- AI 洞察依赖 LLM（智谱 GLM）；未配置/超额/失败时自动**规则兜底**返回结构化要点（来源标「规则分析」）；在「AI 额度设置」检查 API Key 与额度。

**Q17：运行分析消耗 AI 额度吗？**
- 消耗（计入每日 token/调用限制）；无额度自动降级规则，不影响使用；管理员可在「AI 额度设置」调整/重置。

**Q18：库存预警/滞销清单不准确？**
- 库存分析基于阈值（threshold>0 且库存≤阈值判低库存）、近 30 天领用（高周转）、近 90 天无领用（滞销）；请先正确维护阈值与期初库存。

**Q19：怎么调用故障/工单 AI 建议？**
- 在「故障/工单/设备/采购」弹窗内点「🤖 AI 助手 → 生成建议」，一键填入表单（可再次确认刷新）。

**Q20：顶部铃铛有红点，通知怎么处理？**
- 点铃铛打开通知中心，按「报告/预警」查看；点条目跳转对应模块；支持单条/全部已读。红点为未读计数（每 2 分钟轮询更新）。

**Q21：怎么调整每日巡检时间？**
- 通过环境变量 `PATROL_DAILY_HOUR`（默认 8）与 `PATROL_DAILY_MIN`（默认 0）设置，如每日 20:30 设 `PATROL_DAILY_HOUR=20`、`PATROL_DAILY_MIN=30`。

**Q22：决策建议中心「一键采纳」会直接下单吗？**
- 不会直接下单；「一键采纳」生成**采购草稿单**（半自动），需在采购管理查看/完善后正式下单，保障人工确认环节。

**Q23：AI 助手命令类操作安全吗？**
- 命令类（报修/建单）为真实写操作，会记录操作日志；后端在指令内二次校验 `fault:update`/`workorder:create` 权限；操作前请确认输入正确。

| 项 | 值 | 说明 |
|----|-----|------|
| 默认管理员 | 由 `ADMIN_INIT_PASSWORD` 指定；为空则生成 16 位随机强密码并在首次启动日志打印一次 | 首次初始化仅在用户表为空时创建 |
| 密码策略 | ≥10 位 + 字母 + 数字 | 创建/重置强制 |
