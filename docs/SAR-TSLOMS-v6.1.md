# TSLOMS 发布审核报告（SAR）v6.1

> 审核日期：2026-08-16
> 审核依据：`docs/PRD-TSLOMS-v4.3.md`、`docs/SAR-TSLOMS-v6.0.md`、`docs/AI化交通信号灯运维后台系统核心功能清单.md`
> 审核基线：commit `7d44c69`（相对 `origin/main` 超前 3 个提交）
> 审核范围：v6.0 安全整改、质量门恢复、RBAC 覆盖率批次 2，以及当前待提交功能清单文档

## 一、结论摘要

当前基线已经完成上一轮 SAR v5.0 的主要安全和功能整改：

- AI 端点统一受 `ai:ops` 权限保护，NL 建故障/建工单增加业务权限二次校验。
- 停用用户的既有 JWT 即时失效；管理员初始化密码改为环境注入或随机强密码。
- systemd 改用 `EnvironmentFile`，生产 Compose 绑定本机端口并启用 MySQL/Redis/EMQX 认证。
- 实时异常流已具备后端聚合、AI 工作台入口和 NL 查询入口。
- 广播通知已读改为 `notification_reads` 用户级隔离；HTTP Server 增加超时。
- Go 依赖已按 v6.0 报告升级，历史 `govulncheck` 结果为 0 个可达漏洞；前端已有 Vitest 和 Node 冒烟脚本。
- 最新 `7d44c69` 增加 RBAC 角色、权限、用户授权管理的覆盖率测试。

本次独立复测受到 Windows 工作区长期 Node 进程和并行任务资源争用影响：后端全量测试单独运行超过 180 秒未收敛，前端 Vitest worker 也出现超时。因此，本报告对测试结果采用“代码静态复核 + v6.0 已记录证据 + 本轮复测限制”的口径，不把超时冒充为通过；正式发布仍需在干净 CI/预发布环境重跑完整门禁。

当前最大遗留仍是后端总覆盖率。v6.0 记录为 28.5%，最新提交只提升了 handler 的局部覆盖率，尚无本轮全量覆盖率结果达到项目规范要求的 80%。

## 三、已确认的安全与功能门禁

### 3.1 权限与认证

- `main.go` 中 AI 预测、诊断、分析、报告、建议、NL、决策、异常流端点均挂载 `ai:ops`。
- `nl.go` 中命令类工具执行前校验 `fault:update` 或 `workorder:create`，避免自然语言绕过普通业务接口。
- `middleware/auth.go` 在查到用户后校验 disabled 状态，停用用户既有令牌不能继续访问。
- `/ai/decision/adopt` 同时要求 `ai:ops` 和 `purchase:manage`。

### 3.2 通知隔离

- `notification_reads` 表承载广播通知的用户级已读状态。
- `MarkNotificationRead`/`MarkAllNotificationsRead` 返回数据库错误，handler 负责传播错误。
- 仍需在 CI 中固定运行双用户广播通知隔离测试，并验证历史 `notifications` 数据迁移后的兼容性。

### 3.3 部署安全

- systemd 通过 `/etc/tsloms/tsloms.env` 注入敏感配置，避免 `${VAR}` 字面值问题。
- 生产 Compose 将基础设施端口绑定 `127.0.0.1`，Redis 和 EMQX 启用认证，MySQL 使用应用专用账号。
- 生产环境还需把 `systemd-analyze verify`、Compose 配置检查和全新环境启动纳入 CI/发布脚本，不能只依赖静态文件审核。

### 4.1 覆盖率专项

> 更新：本专项已由 **`docs/SAR-TSLOMS-v6.2.md`** 关闭 —— 后端总覆盖率经逐包真实集成测试提升至 **80.5%（≥80% 达标）**。以下为 v6.1 当时的低覆盖记录，供回溯。
项目规范要求单元测试覆盖率不低于 80%。当前仍存在以下低覆盖区域：

- `cmd/server`/路由启动流程缺少可测试拆分；
- handler 主流程和错误分支仍多；
- service 异步巡检、离线检测、超时升级缺少确定性时钟和取消链测试；
- MQTT handler 与协议边界、重连和异常报文场景不足；
- AI 真实数据库聚合、额度、降级和写命令审计仍需集成测试。

因此，当前可以作为 M1 基线，但不能宣称“达到正式发布质量门”。

## 六、审核结论与复审条件

**结论：附条件通过。**

允许将当前干净代码基线作为第一个里程碑提交和打标签，但标签含义应明确为“AI 运维后台 M1 基线”，而非“全量无人值守目标已完成”。

正式全量发布复审前必须满足：

1. 干净 CI 中 `go test`、`go test -race`、`go vet`、`gofmt`、`govulncheck` 全绿；
2. 后端总覆盖率达到 80%，核心路径包含集成测试；
3. 前端 Vitest、Node 冒烟和关键浏览器 E2E 可在无人工修改环境下复现；
4. 生产配置校验、迁移备份/回滚、RPO/RTO 演练完成；
5. 按 `TSLOMS-RP-1.0.md` 完成数据底座、自动调度和 AI 评估的阶段验收。
